How to Use This Dashboard

▼

This dashboard consolidates a four-layer semiconductor supply chain analysis into an interactive monitoring tool. The underlying model scores 5 AI semiconductor companies across 6 structural risk dimensions, calibrated via backtesting against 7 major 2024-2025 price events. Signal cards at the top show real-time price alerts: green = price in entry zone, amber = within 5% of a trigger level, red = stop-loss breached, grey = no signal. These update automatically when live prices are fetched.

Live data: Enter a free Finnhub API key (takes 20 seconds at finnhub.io/register) and click "Fetch Live" for real-time quotes. Without a key, the dashboard shows recently-fetched fallback prices with a stale-data warning. Prices auto-refresh every 60 seconds when a key is active. The dashboard works fully offline with fallback data — the API enhances but isnt required.

Scenario toggle: Switch between Base (60%), Bull (20%), and Bear (20%) to see how allocation weights shift. The allocation bar, deployed meter, signal cards, and cluster compliance all update dynamically. Use this to stress-test exposure under different market regimes.

Catalyst proximity: Events within 14 days glow amber in the timeline with a countdown badge. When a catalyst is imminent, the associated companys trigger card auto-expands so you can see the exact action plan. Company rows in the table are clickable — expand to see full trade triggers, top 3 catalysts with sources, and invalidation criteria.

Updating inputs: All data lives in the DATA object in the script section. Edit prices, risk scores, or catalyst dates directly and refresh. Methodology is documented in the companion markdown files. Data freshness date is in the header — refresh quarterly after each earnings cycle.

Backtest Methodology

▼

Simulation mechanics: The backtest takes each scenario's portfolio weights (Base: AVGO 22%, NVDA 18%, ASML 12%, TSM 9%, ASX 6%, USDC 33% | Bull: 28/22/15/10/8/17 | Bear: 12/8/8/0/0/72) and applies them to 251 trading days of actual closing prices from March 7, 2025 to March 6, 2026. Portfolio value is calculated daily as the weighted sum of each position's return from day 1, with the USDC allocation earning 4% APY (0.011% daily). This is a daily-rebalanced simulation — weights are held constant, not drifting with price changes.

Assumptions: No transaction costs (these are large-cap liquid names with tight spreads). No slippage. Daily closing prices from Yahoo Finance v8 API. USDC yield assumed constant at 4% APY (Spark sUSDC). Entry is day 1 at market prices — this is NOT the same as buying at the entry targets on the trigger cards. The backtest answers "what if you had held these weights for the past year" not "what if you had waited for entry targets."

Key metrics: Cumulative return = total portfolio gain from day 1. Max drawdown = largest peak-to-trough decline during the period. Sharpe ratio = annualized (mean daily return / std dev of daily returns) * sqrt(252), using 0% risk-free rate since USDC yield is already embedded in the portfolio return. Alpha = portfolio return minus benchmark (SPY) return.

Limitations: Past performance does not predict future returns. The backtest period (Mar 2025 — Mar 2026) included the April 2025 systemic selloff and subsequent recovery — a particularly volatile period that may overstate both drawdowns and recovery returns. The model does not account for the stop-loss rules defined in the risk framework, which would have triggered exits during the April drawdown and altered the return profile. A more conservative simulation incorporating stops would show lower drawdowns but also lower recovery returns.

Updating: The historical data is embedded in the HIST object in the script section. To refresh, fetch new data from Yahoo Finance v8 API (endpoint: query2.finance.yahoo.com/v8/finance/chart/TICKER?interval=1d&range=1y) and replace the dates and closes arrays. The backtest engine recalculates automatically on page load.

Correlation Module Methodology

▼

Data sources: Semiconductor stocks (NVDA, AMD, AVGO, TSM, MRVL) from Yahoo Finance v8 API. Crypto AI tokens (TAO, RNDR, AKT, FET) from CoinGecko API. Both cover Mar 7, 2025 to Mar 6, 2026 (251 trading days). Crypto prices are aligned to equity trading dates — weekend crypto prices use Friday close, holidays use prior trading day.

Correlation engine: Pearson correlation is calculated on daily log returns (not raw prices) to avoid spurious correlation from trending series. Rolling windows of 30 and 90 trading days capture short-term regime changes and medium-term structural relationships respectively. The 30-day window is more sensitive to divergences but noisier; 90-day smooths out noise but lags regime changes.

Divergence detection: A divergence is flagged when a pair's rolling correlation drops below 0.2 (or goes negative) while its full-period historical correlation is above 0.5. This identifies moments when assets that normally move together decouple — potentially signaling that crypto AI token prices are reflecting deployment narratives (protocol upgrades, token launches) rather than the semiconductor hardware demand that should drive their fundamentals.

Signal interpretation: A positive divergence (crypto up while semis flat/down) may indicate speculative narrative in crypto AI outrunning actual compute demand. A negative divergence (crypto down while semis up) may indicate crypto-specific risk (regulatory, tokenomics, unlock schedules) unrelated to AI infrastructure fundamentals. Both create potential alpha opportunities for cross-asset positioning.

Limitations: 251 trading days is a short history for correlation analysis. Crypto AI tokens have much smaller market caps than semiconductor stocks, creating asymmetric volatility. CoinGecko daily prices may differ slightly from exchange-specific pricing. The divergence threshold (0.2) is heuristic — not statistically optimized. This tool surfaces signals for further investigation, not automatic trade triggers.

Signal Pipeline Methodology

▼

Signal categorization: Each of the 87 detected divergence events is categorized into one of three types based on price action during the divergence window. Semi Leads: the semiconductor stock outperformed while the crypto AI token lagged (semi return > crypto return, with opposing signs or >5% gap). Crypto Leads: the crypto token outperformed while the semi lagged. Full Decouple: the two assets moved in opposite directions (one positive, one negative, both >2% magnitude). This last category represents the strongest divergence signal.

Backtest methodology: For each categorized divergence event, we measure the forward return of the recommended trade asset (the underperformer) over 7, 14, and 30 trading days following the end of the divergence. The "catch-up" hypothesis is that the lagging asset mean-reverts toward the leader. A "win" is defined as positive return on the trade asset within the window. Win rates and average returns are computed per signal type per window.

Conviction scoring: Each signal receives a composite score from 0 to 100 based on four components: (1) Hit rate (40%): the backtested 14-day win rate for that signal type, adjusted downward for small sample sizes. (2) Depth (25%): how deeply the 30-day rolling correlation dropped — more negative correlations indicate stronger divergence. (3) Duration (15%): longer divergence periods suggest a more established regime break. (4) Catalyst (20%): signals coinciding with known catalyst events receive full marks, as catalyst-driven divergences historically resolve more predictably.

Trade card generation: For divergences ending within the last 20 trading days, trade cards are generated with: Entry at current price of the underperforming asset, Stop-loss at 1.5x the backtested average loss for the signal type (minimum 3%), Take-profit at 1.2x the backtested average win (minimum 5%), Position sizing tiered by conviction (high ≥65: 3-5%, medium 45-64: 1-3%, low <45: 0.5-1%).

Forward-data filtering: All backtest statistics and historical examples are computed exclusively from divergence events with complete forward data windows. An event requires the full 14 trading days of post-divergence price data to be included. Events ending within 14 days of the dataset boundary are excluded from hit-rate calculations and the historical examples table. This eliminates truncated returns that would bias statistics and produce N/A values. The Pipeline Quality Metrics panel shows before vs. after filtering counts so the data loss from filtering is transparent.

Signal reliability scoring: Each signal type receives a reliability score (0-100) computed from three equally-important factors: (1) Data completeness (35%): percentage of events in that category that have complete 14-day forward data — higher is better. (2) Sample size (30%): total number of events for that type, scaled so 20+ events = full marks. (3) Directional consistency (35%): the filtered 14-day win rate for the type — measures how consistently the catch-up trade produces positive returns. Scores above 70 = High reliability, 45-69 = Medium, below 45 = Low. The signal table and trade cards are sorted by reliability first, then conviction, so the most statistically trustworthy signals surface at the top.

Reliability decay monitoring: The decay monitor computes rolling reliability scores at every 5-day step across the dataset for 30, 60, and 90-day windows. At each step, only divergence events within the trailing window are included, and reliability is recalculated from their completeness, sample size, and directional consistency. A signal type is flagged as "Decaying" when its current rolling score drops more than 20% below its all-time score. A regime-change alert triggers when 2+ types decay simultaneously — indicating a broad shift in market structure that invalidates the historical signal patterns.

Signal freshness: Each trade card receives a freshness indicator derived from the decay analysis: Fresh (<10% below all-time), Aging (10-19% below), or Stale (≥20% below, matching the decay threshold). Trade cards with Stale signals are visually deprioritized (dimmed) to discourage deployment into eroding signals.

Execution engine: The regime-aware execution engine bridges signal intelligence to capital deployment. The regime classifier maps current decay signals to one of 4 states (Neutral, Systemic, Divergence, Earnings) using the same logic as the playbook. Confidence is a 0-100 composite of decay severity (40%), type breadth (30%), and backtest accuracy (30%). The delta calculator compares current base-scenario weights against the playbook-prescribed target weights for the detected regime, outputting position-level overweight/underweight amounts. The rebalancing queue prioritizes by delta magnitude and assigns urgency tiers: Immediate (alert active + delta ≥10%), Next Session (alert active + delta ≥3%, or delta ≥5%), Watch (all others). The 90-day regime timeline replays the decay detection logic at 3-day intervals over the trailing 90 trading days, classifying each point into a regime state and marking transitions. The stress test replays each backtested TP event through the engine and verifies the output matches the playbook-prescribed weights and generates a valid trade queue.

Regime-transition playbook: The playbook maps 3 regime categories (Systemic Risk-Off, Divergence/Decouple, Earnings/Rotation) to specific portfolio weight overrides. For each backtested event, P&L is computed over a 30-day forward window: "No Action" holds base weights, "Playbook" switches to category-specific defensive/offensive weights at the alert timestamp (for TPs) or hypothetically 10 days before event (for missed). Each rebalance incurs 10bps slippage. The cumulative P&L chart replays the full period, switching to playbook weights at every alert (both TPs and FPs), holding for 20 trading days before reverting to base. This captures the full cost of false positives. The regime-readiness indicator maps current live decay signals to the nearest playbook action by inferring regime type from which signal types are decaying: all 3 = Systemic, SEMI_LEADS present = Divergence, otherwise Earnings/Rotation.

Regime-change backtester: The backtester replays historical data through the decay detection engine to validate whether regime-change alerts predict actual market shifts. Five historical regime events are defined from the dataset period (Apr 2025 tariff selloff, Jul 2025 ASML Q2 miss, Oct 2025 AVGO-OpenAI deal, Nov 2025 Blackwell Ultra, Feb 2026 NVDA Q4 earnings). For each rolling window (30d/60d/90d), the engine steps through every 3 trading days, computing per-type rolling reliability against a running peak (no lookahead bias — the "all-time" baseline only uses data available at that point). A regime alert fires when 2+ signal types simultaneously decay 20%+ below their running peak. Alerts firing within 30 trading days before a regime event = True Positive. Alerts not near any event = False Positive. Events without preceding alerts = Missed. The optimal window is selected by maximizing accuracy × (1 - FP rate) × lead-time bonus. Threshold adjustments are recommended when FP rate exceeds 40% (raise threshold) or when missed events exceed 1 with low FP rate (lower threshold).

Limitations: 87 divergence events across 20 pairs over 251 days is a limited sample. Forward-data filtering further reduces the testable sample. Rolling window reliability at shorter windows (30d) can be noisy due to small sample sizes within the window. The 20% decay threshold is heuristic — it was chosen to balance sensitivity against false alarms but is not statistically calibrated. Both conviction and reliability scores are heuristic, not statistically optimized. These are signal candidates for further investigation, not automatic trade triggers. Always size positions according to the portfolio risk rules defined in the allocation model.
